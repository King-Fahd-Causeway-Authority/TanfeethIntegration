# منصة التكامل مع تنفيذ
## دليل المنصة والتشغيل – نسخة هيئة الحكومة الرقمية (DGA)

### 1. تعريف المنصة
منصة إلكترونية داخلية تم تطويرها في **المؤسسة العامة لجسر الملك فهد** لتمكين الموظفين المخولين من إعداد وإنشاء وإرسال ومتابعة طلبات التنفيذ إلكترونياً من خلال التكامل مع **منصة تنفيذ التابعة لديوان المظالم**.

تهدف المنصة إلى أتمتة إجراءات طلبات التنفيذ، تقليل الإدخال اليدوي، التحقق من اكتمال البيانات، تنظيم المرفقات، إرسال الطلبات عبر خدمة التكامل، واستقبال نتائج المعالجة ومتابعة حالة الطلب.

### 2. نطاق الاستخدام
المنصة مخصصة للاستخدام الداخلي من قبل المستخدمين المخولين في المؤسسة العامة لجسر الملك فهد. ولا يتم منح المستخدم إمكانية الدخول اعتماداً على وجود حساب نطاق فقط؛ بل يجب أيضاً أن يكون المستخدم مصرحاً له باستخدام التطبيق وفق إعدادات المستخدمين داخل المنصة.

### 3. تسجيل الدخول والمصادقة
تعتمد المنصة على **Active Directory (AD)** الخاص بالمؤسسة للتحقق من هوية المستخدم.

مسار الدخول:
1. يدخل المستخدم بيانات حساب المؤسسة.
2. يتم التحقق من بيانات الاعتماد من خلال Active Directory.
3. بعد نجاح المصادقة، تتحقق المنصة من أن المستخدم مسجل ومفعّل ضمن مستخدمي التطبيق.
4. عند نجاح التحقق يتم إنشاء جلسة المستخدم والسماح له باستخدام الوظائف المخولة له.

كلمات مرور موظفي المؤسسة لا يفترض تخزينها ككلمات مرور محلية داخل قاعدة بيانات التطبيق.

بيانات Domain أو Service Account أو أي بيانات اعتماد خاصة بالبيئة الفعلية غير مضمنة في نسخة DGA.

### 4. الوظائف الرئيسية
- تسجيل الدخول والتحقق من المستخدم عن طريق Active Directory.
- إدارة المستخدمين المخولين باستخدام المنصة وفق الوظائف المتاحة.
- إنشاء طلب تنفيذ جديد.
- إدخال بيانات الطلب عبر مراحل منظمة.
- إدخال بيانات المنفذ ضده وفق نوعه والبيانات المطلوبة.
- إدخال بيانات المطالبة.
- إدخال بيانات السند التنفيذي.
- إضافة المرفقات المطلوبة.
- التحقق من الحقول الإلزامية قبل الإرسال.
- إرسال الطلب إلى خدمة التكامل مع منصة تنفيذ.
- استقبال نتيجة الإرسال والبيانات المرجعية التي تعيدها خدمة التكامل.
- متابعة طلبات التنفيذ وحالاتها.
- الاستعلام عن حالة الطلب من خلال التكامل.
- تسجيل العمليات ونتائج التكامل اللازمة للمتابعة والتدقيق وفق السياسات المعتمدة.

### 5. رحلة المستخدم
#### تسجيل الدخول
يفتح المستخدم رابط المنصة الداخلي ويسجل الدخول باستخدام حساب المؤسسة.

#### إنشاء طلب
يختار المستخدم إنشاء طلب تنفيذ، ثم يكمل المراحل الظاهرة في واجهة المنصة:
1. **بيانات الطلب** – البيانات الأساسية الخاصة بطلب التنفيذ.
2. **المنفذ ضده** – بيانات الطرف المنفذ ضده وفق النوع المختار.
3. **المطالبة** – بيانات المطالبة المالية أو البيانات المرتبطة بها حسب الطلب.
4. **السند والإرسال** – بيانات السند التنفيذي، المرفقات، المراجعة النهائية وإرسال الطلب.

#### التحقق من البيانات
تتحقق المنصة من الحقول المطلوبة وفق نوع الطلب والطرف قبل السماح باستكمال عملية الإرسال.

#### الإرسال
عند اعتماد البيانات، تقوم المنصة بإرسال الطلب Server-to-Server إلى خدمة التكامل مع منصة تنفيذ.

#### المتابعة
يمكن للمستخدم المخول متابعة الطلبات وحالتها والنتائج المرجعة من خدمة التكامل.

### 6. المكونات والتكاملات
#### Active Directory
يستخدم للتحقق من هوية موظفي المؤسسة.

إعدادات البيئة المطلوبة:
- `ActiveDirectory:Domain`
- `ActiveDirectory:ServiceAccountUsername` عند الحاجة
- `ActiveDirectory:ServiceAccountPassword` عند الحاجة

يجب توفير هذه القيم من خلال إعدادات آمنة في بيئة التشغيل وعدم تضمينها في Source Control.

#### قاعدة البيانات
تستخدم قاعدة البيانات لحفظ بيانات التطبيق والمستخدمين وطلبات التنفيذ والمعلومات التشغيلية وسجلات التكامل المطلوبة.

الإعداد المطلوب:
- `ConnectionStrings:LogTanfeethIntegration`

Connection String الفعلي غير موجود في نسخة DGA.

#### التكامل مع منصة تنفيذ
التكامل يتم Server-to-Server.

إعدادات الربط المطلوبة:
- `ExternalService:BaseApiUrl`
- `ExternalService:x-Gateway-APIKey`
- `ExternalService:App-Key`

لا تحتوي نسخة DGA على Endpoint فعلي أو API Keys.

للحصول على صلاحيات الربط أو Endpoint أو مفاتيح التكامل، يجب التنسيق من خلال القنوات الرسمية مع الجهة المالكة لخدمة منصة تنفيذ وبالتنسيق مع الفريق المختص في المؤسسة العامة لجسر الملك فهد.

### 7. متطلبات الشبكة
لا تحتاج واجهة المنصة إلى Internet عام أثناء التشغيل. ملفات CSS وJavaScript والأيقونات والمكونات الأمامية المطلوبة للتشغيل موجودة محلياً داخل المشروع.

يحتاج خادم التطبيق فقط إلى الوصول الشبكي المصرح به إلى:
- Active Directory / Domain Controllers.
- SQL Server الخاص بالتطبيق.
- API/Gateway الخاص بمنصة تنفيذ.

يوصى بتطبيق Network Allow-list للوجهات والمنافذ المطلوبة فقط وفق سياسات الأمن السيبراني.

### 8. التشغيل في بيئة بدون Internet
المكتبات الأمامية المستخدمة بواسطة المنصة يجب أن تكون مستضافة محلياً داخل `wwwroot`، ولا يعتمد تشغيل واجهة المستخدم على CDN أو Google Fonts أو مكتبات JavaScript يتم تحميلها من الإنترنت.

قد يحتاج جهاز التطوير إلى مصدر NuGet معتمد أثناء Restore/Build. أما خادم التطبيق بعد نشر الحزمة فلا يحتاج Internet لهذا الغرض، لأن الملفات والـ assemblies المطلوبة تكون ضمن مخرجات النشر.

### 9. إعدادات نسخة DGA
نسخة DGA هي نسخة Source Code مخصصة للمراجعة ولا تحتوي على بيانات البيئة الفعلية.

تم استبدال الإعدادات الحساسة بقيم Placeholder مثل:
- `__CONFIGURE_IN_DEPLOYMENT_ENVIRONMENT__`
- `__KFCA_AD_DOMAIN__`
- `__CONFIGURE_SECURELY__`
- `__TANFEETH_API_BASE_URL__`

يتم حقن القيم الفعلية فقط في بيئة النشر المصرح بها باستخدام Environment Variables أو Secret Store أو آلية إدارة الأسرار المعتمدة لدى الجهة المستضيفة.

### 10. البيانات الحساسة غير المضمنة في نسخة DGA
لا ينبغي أن تحتوي الحزمة المرسلة للمراجعة على:
- Connection Strings فعلية.
- أسماء أو عناوين خوادم البيئة الفعلية.
- API Keys.
- App Keys.
- Access Tokens.
- كلمات مرور.
- بيانات Service Accounts.
- بيانات AD الفعلية.
- بيانات مستخدمين إنتاجية.
- Logs إنتاجية.
- ملفات Publish تحتوي على إعدادات Production.
- Certificates أو Private Keys.
- أسرار محفوظة داخل Source Code.

### 11. TLS والشهادات
يجب التحقق من شهادات TLS بشكل طبيعي وعدم تجاوز Certificate Validation.

يجب أن تكون سلسلة شهادة خدمة التكامل موثوقة لدى خادم التطبيق. ولا يسمح باستخدام آليات مثل `DangerousAcceptAnyServerCertificateValidator` في البيئة الفعلية.

### 12. خطوات إعداد المشروع للمراجع أو المطور
1. فتح Solution الخاصة بالمشروع في Visual Studio بإصدار يدعم .NET المستخدم في المشروع.
2. Restore لحزم NuGet من المصدر المعتمد.
3. إعداد بيئة اختبار غير إنتاجية.
4. توفير إعدادات AD الاختبارية بشكل آمن.
5. توفير Connection String لقاعدة بيانات الاختبار.
6. توفير Endpoint ومفاتيح Integration خاصة ببيئة الاختبار عند توفر صلاحية الربط.
7. التأكد من الوصول الشبكي المطلوب.
8. Build للمشروع.
9. تشغيل التطبيق.
10. تسجيل الدخول بحساب AD مخول ومسجل في مستخدمي التطبيق.
11. اختبار إنشاء طلب وإرساله ومتابعة حالته.

### 13. النشر
عند نشر المنصة:
- يتم Build/Publish من مصدر موثوق.
- يفضل النشر إلى مجلد جديد بدلاً من دمج ملفات Publish قديمة وجديدة.
- لا يتم تضمين الأسرار داخل Source Code.
- يتم ضبط `ASPNETCORE_ENVIRONMENT` حسب البيئة.
- يتم توفير إعدادات Production من مصدر إعدادات آمن.
- يتم تثبيت/الثقة في شهادات TLS اللازمة.
- يتم منح حساب تشغيل التطبيق أقل صلاحيات لازمة.
- يتم تقييد الوصول الشبكي للوجهات المطلوبة فقط.
- يتم تطبيق سياسات النسخ الاحتياطي والمراقبة والاحتفاظ بالسجلات المعتمدة.

### 14. اعتبارات أمنية
- المصادقة تتم من خلال Active Directory.
- السماح باستخدام التطبيق يخضع أيضاً لصلاحية المستخدم داخل المنصة.
- لا يتم تسجيل Passwords أو API Keys أو Tokens في Logs.
- يجب حماية سجلات Request/Response لأنها قد تحتوي على بيانات أعمال أو بيانات شخصية.
- يجب تحديد صلاحيات الوصول إلى السجلات ومدة الاحتفاظ بها.
- يجب مراجعة المستخدمين المخولين دورياً.
- يجب إلغاء أو تعطيل المستخدمين الذين لم تعد لديهم حاجة وظيفية للوصول.
- لا يتم فتح Internet عام لخادم التطبيق لمجرد تشغيل واجهة المستخدم.
- يجب حفظ الأسرار خارج Source Control.
- يجب استخدام HTTPS/TLS للاتصالات التي تتطلب ذلك.

### 15. الدعم الفني والتنسيق
للاستفسارات المتعلقة بالمنصة، إعداد البيئة، التشغيل، أو المشاكل الفنية، يتم التواصل مع **فريق الدعم/الفريق التقني في المؤسسة العامة لجسر الملك فهد** من خلال قنوات التواصل المعتمدة.

أما ما يتعلق بـ:
- تفعيل التكامل مع منصة تنفيذ.
- الحصول على صلاحيات الربط.
- الحصول على Endpoint.
- إصدار أو تغيير مفاتيح API.
- مشاكل الوصول إلى خدمة تنفيذ.

فيتم التنسيق عبر المسار الرسمي مع الجهة المالكة لخدمة منصة تنفيذ وبالتنسيق مع الفريق المختص في المؤسسة العامة لجسر الملك فهد.

### 16. ملاحظة لهيئة الحكومة الرقمية
الحزمة المقدمة لهيئة الحكومة الرقمية هي **DGA Sanitized Source Review Package** مخصصة للمراجعة الفنية والأمنية.

عدم وجود بيانات الاتصال الفعلية أو مفاتيح التكامل أو بيانات Active Directory داخل الحزمة مقصود لحماية بيئة المؤسسة ولا يمثل نقصاً في التصميم الوظيفي للمنصة.

القيم الحقيقية يتم توفيرها فقط داخل بيئات التشغيل المصرح بها وفق آليات إدارة الإعدادات والأسرار المعتمدة.
